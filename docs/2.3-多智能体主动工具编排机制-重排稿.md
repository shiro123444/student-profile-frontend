## 2.3 多智能体主动工具编排机制

为解决传统教育类 AI 系统“能回答但难执行、能建议但难闭环”的问题，PathMind AI 在架构上引入多智能体主动工具编排机制。该机制不以单一模型连续输出文本为核心，而是以“角色分层、任务委托、工具执行、结果回流”为主线，构建面向真实教学场景的可执行闭环。系统在一次请求内可完成任务识别、Agent 路由、工具调用、审批控制、审计记录与反馈追踪，实现从“建议生成”向“任务交付”的能力升级。

### 2.3.1 Agent 角色划分与职责边界

在项目实施中，我们首先解决“谁来做什么”的问题。若缺少清晰的角色边界，多智能体系统容易出现职责重叠、相互覆盖或循环委托，导致响应不稳定与成本上升。

基于高校职业发展场景，系统将 Agent 能力划分为四类：

1. 中枢协调类：以 command-center 为核心，负责跨模块任务识别、委托分发、状态汇总与运行态观测。
2. 领域能力类：career-advisor、learning-coach、mbti-analyst、document-reader、note-assistant、graph-analyst 分别承担职业规划、学习路径、人格分析、资料检索、知识沉淀与图谱探索。
3. 执行控制类：web-coder 与 code-reviewer 负责高专业度、高风险任务，配套沙箱与审批机制。
4. 入口交互类：quick-qa 与 homepage-guide 负责轻量问答、首页导览与低门槛分流。

通过上述分层，系统形成了“中枢调度 + 专业执行 + 统一交互入口”的结构，既保证复杂任务可拆解，也保证简单问题可快速响应。

### 2.3.2 任务委托逻辑与协同策略

在角色分工确定后，第二个关键问题是“任务如何在 Agent 之间安全流转”。为此，系统在委托链路中引入可解释、可约束的协同策略。

任务委托采用两级机制：

1. 单任务委托（delegate_to_agent）：当前 Agent 将子任务委托给目标 Agent，并携带必要上下文与期望输出格式。
2. 批任务委托（delegate_batch_agents）：一次请求拆分为多个子任务，支持 best_effort 与 all_or_nothing 两种执行语义，用于并行协同或事务式交付。

为避免委托失控，系统在运行时执行四项约束：

1. 白名单约束：每个 Agent 仅可委托给预定义目标集合。
2. 深度约束：限制最大委托层级，防止无限下钻。
3. 环路约束：检测 chain 中重复节点，阻断循环委托。
4. 同名约束：禁止自委托，避免无效调用。

该逻辑使委托过程从“模型自由发挥”变为“可治理协作协议”，显著提升多 Agent 任务编排稳定性。

### 2.3.3 工具调用流程与执行控制

在任务确定后，系统进入工具执行阶段。与传统“直接调用外部接口”的方式不同，PathMind AI 采用“流式事件驱动 + 风险分级控制”的调用流程。

完整流程如下：

1. 前端发起流式请求，进入 Go 网关，再转发至 Python Agent 服务。
2. AgentService 根据 runtime 参数决定执行模式（fast/balanced/deep）及是否启用 orchestrator。
3. 引擎层生成工具调用请求，触发 tool_call 事件并进入权限判定。
4. 低风险工具直接执行；高风险工具进入 approval_request，等待用户 approve/reject。
5. 工具执行结果通过 SSE 持续回传，包含 tool_retry、tool_fallback、approval_result、done 等事件。
6. 若涉及跨 Agent 协同，同步产生 agent_handoff 或 agent_handoff_batch 事件，前端可实时展示任务链路。

该流程的核心优势是“执行过程可视化”：用户不仅看到最终答案，也能看到任务如何被拆解、调用了什么工具、为何重试或回退。

### 2.3.4 闭环机制：反馈、审计与再规划

多智能体系统的关键不在“调用成功一次”，而在“能否持续稳定完成任务”。因此，项目将闭环机制分为四层：

1. 计划闭环：启用 orchestrator 时，先规划再执行；执行后触发 critique，必要时动态 replan。
2. 安全闭环：高风险工具必须审批；超时默认拒绝；审批结果与等待时长进入指标体系。
3. 审计闭环：关键操作异步写入审计端点，记录 agent、engine、mode、tool、risk、approved、status、duration 等字段。
4. 记忆闭环：流式完成后自动写入会话摘要与上下文，支持后续会话恢复与多轮任务连续执行。

同时，图谱类操作支持执行回执上报（feedback），下一轮推理可引用上一轮真实执行状态，避免“模型认为已执行但前端未落地”的状态漂移。

### 2.3.5 阶段成效与结论

通过“角色分层 + 委托约束 + 工具风控 + 反馈审计”四位一体的机制，PathMind AI 已从问答型助手演进为可执行智能体系统。其阶段性成效体现在：

1. 复杂任务可被稳定拆解并跨 Agent 协同完成。
2. 高风险动作具备可审批、可追踪、可回放能力。
3. 前端可实时呈现编排过程，提升用户信任与可解释性。
4. 运行数据可持续沉淀，为后续策略优化与产品迭代提供依据。

综上，多智能体主动工具编排机制不仅提升了系统任务完成质量，也构建了教育场景可持续运行所需的治理基础，为后续商业化落地与规模化推广提供了核心技术支撑。
